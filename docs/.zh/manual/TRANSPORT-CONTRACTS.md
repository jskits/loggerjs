# 传输契约矩阵

本矩阵把每个一方 transport 与其公开入口、源码文件和契约测试一一对应，目的是让可靠性说法可以被核查：原始线上协议 transport 必须暴露投递失败；生产级投递必须明确说明使用的包装器或队列；生命周期行为必须有对应的测试路径。

`pnpm verify:transport-contracts` 会把本页与各包的导出和仓库文件树进行核对。新增 transport 源文件或公开的 transport 子路径时，必须在同一次变更中更新本矩阵。

## 契约规则

- 原始 HTTP/厂商 transport 会把非 2xx 响应和被拒绝的 `fetch` 调用作为失败向上传递；除非外面包了包装器，否则不会静默重试。
- 原始线上协议 sink 要用于生产投递，需要 `batchTransport()`、`retryTransport()`、`fallbackTransport()`，或使用一个在文档中说明了自身队列/重试行为的 transport。
- 依赖运行时的 transport 必须说明所依赖的平台能力，并测试依赖不可用或失败的情况。
- 持久化路径必须在测试中体现 `flush()` 或持久化/重放行为。
- 仅用于测试或仅用于显示的 transport 必须明确说明这一点，不能暗示具备持久投递能力。
